# Epic: `[ENG-2075]` Streamlit & Interactive Data App Platform on BigQuery (Replace Streamlit in Snowflake)

## Epic template

| Section | Details |
| :--- | :--- |
| **Context** | **Executive Summary & Strategic Context**<br>Transurban is retiring Snowflake in favour of **BigQuery** and moving **100% to Google Cloud**, standardizing on **Google Agentspace** as the enterprise AI/discovery portal, **Google Antigravity** (and Claude Code / Gemini CLI) for agentic engineering, and the **Transurban Sensible Defaults (DDD0–DDD7)** defined by the Software Engineering in the Age of AI Lead (**SEAL**) team.<br><br>Today, data analysts and engineers build and host interactive data applications using **Streamlit in Snowflake (SiS)**. As workloads migrate to BigQuery under Project Nova (`BQM`), SiS has no single 1:1 drop-in native button inside the BigQuery console. Rather than lifting-and-shifting every legacy script into a container—or conversely, forcing every bespoke interactive engineering dashboard to be rewritten from scratch—we are establishing a **paved-road, serverless interactive data app platform on Cloud Run v2 + BigQuery**, seamlessly integrated with **Google Agentspace** and accelerated by **agentic migration skills**.<br><br>**Option 1 Hybrid Golden Path Architecture (Implemented Pilot: `ncx-portal-emissions-app`)**<br>In alignment with SEAL guidance (Phil Wait / Scott Penno), the platform adopts the **Option 1 Hybrid Golden Path Container** pattern: a governed Python 3.12 + Streamlit (`uv`, `pyproject.toml`) Cloud Run v2 runtime that serves **both** native Streamlit widgets (`st.dataframe`, `st.metric`) **and** rich self-contained interactive HTML5/CSS/JS/SVG/Chart.js frontends via `st.components.v1.html()`, backed by dynamic Python server-side data connectors (**BigQuery Storage Read API**, **Amazon Redshift**, **Snowflake**, **AWS S3 / Athena**, and **Splunk**).<br><br>**What Do We Mean by "App"? (The 4-Tier SiS Disposition Taxonomy)**<br>Not every legacy SiS script should become a containerized web application. Every workload audited in `[ENG-2087]` is triaged into one of four target patterns:<br>1. **Retire** (*Unused / Ad-hoc Script*, 0 queries in 90d) → **Delete / Archive in GitHub (DDD1)**.<br>2. **Replace (BI Dashboard)** (*Read-only KPI charts & standard filter tables*) → **Looker / Looker Studio Pro** on BigQuery BI Engine.<br>3. **Reimagine (No-Code Agent)** (*Simple lookup forms & natural-language table Q&A*) → **Google Agentspace Agent Designer** + **MCP Toolbox for BigQuery**.<br>4. **Migrate (Stateful Data App — *this platform*)** (*Custom multi-step Python workflows, engineering telemetry schematics, interactive HTML/SVG/Chart.js tools, write-backs/approvals, simulations, ML inference*) → **Cloud Run v2 + Direct IAP + BigQuery** provisioned via the `StreamlitApp` Pulumi (Go) component and registered in **Google Agentspace**. |
| **Stakeholders** | • **SEAL / Platform Engineering:** Scott Penno (Reporter / Lead), Phil Wait (Golden Path & Dynamic Data Architecture), Jonathan Teow (Architecture & Taxonomy Alignment)<br>• **Asset Management & Tunnel Operations (Pilot Owner):** Azam Muhammad (`ncx-portal-emissions-app` — NorthConnex Tunnel Ventilation & Portal Emission Analytics)<br>• **CloudOps / Landing Zone & Networking:** Julien Bonastre (VPC, Zscaler ZPA, Cloud Workstations, `DDD7 §6.5`)<br>• **Data Platform / Project Nova (`BQM`):** BigQuery dataset migration & schema parity owners<br>• **Cyber Security & NAT Compliance:** Threat model (`ENG-2085`), Direct IAP + Workforce Identity Federation, and NAT-restricted workload sign-off |
| **Objective** | • **Decommission Streamlit in Snowflake (SiS)** cleanly ahead of the Snowflake contract exit by classifying all existing SiS apps (`ENG-2087`) and migrating stateful apps using an agentic factory (`ENG-2088`).<br>• **Deliver the Option 1 Hybrid Golden Path Template (`pe-ws4-streamlit-bq-template`)** allowing engineers and analysts to spin up production-grade Streamlit **and/or** custom interactive HTML/SVG/Chart.js apps on Cloud Run v2 without learning Docker, IAM, or Terraform/Pulumi from scratch.<br>• **Enforce Zero-Trust Identity & FinOps Guardrails by Default:** Direct Cloud IAP (`--iap`) with Entra ID Workforce Identity Federation (`X-Goog-Authenticated-User-Email`), zero static JSON keys, mandatory BigQuery query labels (`app`, `env`, `user_email`), and a `5 GiB` `maximum_bytes_billed` circuit breaker.<br>• **Achieve Radical Developer Velocity:** `< 15 minutes` Time to First Commit on ZPA Cloud Workstations (`DDD7`) and `< 1 hour` Time to First Deployed App in `dev` via reusable GitHub Actions (`DDD2`) and the `StreamlitApp` Pulumi Go component (`DDD5`).<br>• **Unify Discovery & Agentic Workflows in Google Agentspace:** Register every hosted app in Google Agentspace with an A2A v0.3 Agent Card (`.well-known/agent.json`) and an embedded ADK / Gemini 2.5 Flash conversational sidekick. |

### RAID

| Category | Details |
| :--- | :--- |
| **Risk** | • **R1 — Direct IAP + Entra ID Workforce Identity Pool Compatibility (Medium Likelihood / High Impact):** Cloud Run Direct IAP (`--iap`) with Workforce Identity Pools or WebSocket timeouts may hit org-policy edge cases. *Mitigation:* Validate in `ENG-2076` during Week 1; fallback is External Application Load Balancer + IAP wired inside the `StreamlitApp` Pulumi Go component.<br>• **R2 — BigQuery Slot Contention & Runaway Query Costs (High Likelihood / Medium Impact):** Streamlit's top-to-bottom script re-execution on every widget interaction can trigger repetitive multi-gigabyte scans. *Mitigation:* `src/bq.py` enforces `@st.cache_data(ttl=600)`, `st.fragment` partial reruns, `maximum_bytes_billed = 5 GiB` circuit breaker, and dry-run cost estimation (`ENG-2080`).<br>• **R3 — Analyst Friction Moving from Browser-Based SiS to Git/IDE (Medium Likelihood / Medium Impact):** Data analysts accustomed to editing Python in the Snowflake web UI may find Git/Docker intimidating. *Mitigation:* Pre-configured Cloud Workstations (`DDD7`), Google Antigravity + `migrate-sis-to-bq-streamlit` skill (`ENG-2088`), and Option 1 `src/template_engine.py` allowing analysts to drop existing HTML/JS/SVG files directly into `src/templates/`.<br>• **R4 — Data Exfiltration / Over-Privileged Service Accounts (Low Likelihood / High Impact):** Shared runtime Service Accounts with broad BigQuery access could expose restricted datasets if IAP is misconfigured. *Mitigation:* Dedicated per-app Service Account provisioned via Pulumi (`ENG-2077`), mandatory `--iap` org policy check, Caller's Rights WIF pattern (`ENG-2078`) for PII/sensitive data, and `ENG-2085` security sign-off.<br>• **R5 — Snowflake Decommissioning Timeline Pressure (Medium Likelihood / High Impact):** Late discovery of complex SiS apps could delay Snowflake exit. *Mitigation:* Execute `ENG-2087` audit in Week 1 and already completed the Option 1 reference pilot (`ncx-portal-emissions-app`) to prove out the end-to-end architecture. |
| **Assumptions** | • Target BigQuery datasets (e.g., `tu-data-edw-pr-1.a113_roadside`, `wcx_roadside`, `a101_roadside`, `a108_roadside`) are co-located in `australia-southeast1` (Sydney).<br>• The existing Entra ID Workforce Identity Pool (`locations/global/workforcePools/agentspace-entra-id-p-oidc-exnat`) is available for workforce authentication.<br>• Developers have access to Zscaler ZPA, Cloud Workstations (`DDD7`), and `C:\Program Files\Python314\python.exe` / Python 3.12+ container toolchains. |
| **Issues** | • **I1 — Target GCP Hosting Project Topology:** Confirm in `ENG-2076` whether Cloud Run services deploy into dedicated app-hosting projects (`tu-data-apps-dev` / `tu-data-apps-prod`) querying `tu-data-edw-pr-1` cross-project, or directly inside domain projects.<br>• **I2 — Pulumi State Backend Standardisation:** Confirm in `ENG-2077` whether `StreamlitApp` state is stored in Pulumi Cloud (Enterprise) or a GCS state backend per SEAL `DDD5` conventions.<br>• **I3 — Snowflake Hard Cutover Date:** Confirm exact SiS retirement deadline with the Project Nova (`BQM`) program lead. |
| **Dependencies** | • **CloudOps / Landing Zone (Julien Bonastre):** VPC Service Controls perimeters, Zscaler ZPA routing, and Cloud Workstations readiness (`DDD7 §6.5`).<br>• **Project Nova (`BQM` Team):** Availability and schema parity of migrated BigQuery datasets for legacy SiS workloads.<br>• **SEAL Platform (`PE-WS4`):** Access to `transurban/pulumi-components`, `transurban/code-skills`, JFrog Artifactory/Xray, and SonarQube quality gates.<br>• **Cyber Security & NAT Governance:** Timely review and approval of the `ENG-2085` threat model and NAT compliance checklist. |
